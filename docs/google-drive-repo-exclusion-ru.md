# Как вынести проект из-под Google Drive (и почему это чинит сборку)

Русская инструкция для заказчика, без терминальных предположений. Делать по одному шагу за раз, после каждого ключевого шага — свериться с ожидаемым результатом.

## Зачем это вообще нужно

Папка `C:\Users\Administrator\lox-voice` синхронизируется Google Drive. Из-за этого Drive кладёт в каждую подпапку служебный файл `desktop.ini`. обычно он безвреден, но два места в проекте он ломает:

- `.git\refs\` — git обязан видеть там только ссылки, а `desktop.ini` читает как битую → `git fetch` падает с `fatal: bad object refs/desktop.ini`, пуш в прод невозможен;
- `.next\cache\turbopack\` — кэш сборки Next.js, где все имена должны быть числами → `npm run build` падает с `invalid digit found in string`.

Агент уже закрыл это автоматической чисткой (`npm run gate` и `scripts/git-state.sh` убирают мусор перед сборкой и fetch), но чистка — костыль. Настоящее решение — чтобы Drive не лезал внутри рабочего репозитория. Второе, более важное: раз папка синхронизируется, копии `.env.local` и `.env.test` с настоящими токенами лежат в вашем Google Drive.

## Вариант A (рекомендую) — перенести репозиторий из синхронизируемой папки

1. Закройте редактор/терминалы, которые держат открытой папку проекта, и остановите локальный сайт (если запущен).
2. Откройте «Этот компьютер» и создайте новую папку вне Drive, например `C:\work`.
   Ожидаемый результат: `C:\work` существует, и внутри неё нет служебных файлов `.tmp.driveupload` / `.tmp.drivedownload`.
3. Скопируйте папку проекта целиком: из `C:\Users\Administrator\lox-voice` → в `C:\work\lox-voice` (обычное «Копировать → Вставить», не «Вырезать», чтобы оригинал остался запасным).
   Ожидаемый результат: `C:\work\lox-voice\.git` на месте, `C:\work\lox-voice\package.json` открывается.
4. Откройте в новой папке терминал и выполните `git status`.
   Ожидаемый результат: список изменений без ошибок, в конце нет строк `desktop.ini` (они теперь в `.gitignore`).
5. Выполните `npm ci`, затем `npm run build`.
   Ожидаемый результат: сборка доходит до конца и заканчивается без `Failed to open database`.
6. Когда убедитесь, что всё работает, переименуйте старую папку в `lox-voice-old` (не удаляйте сразу) и удалите её позже, когда ничего не понадобится.
   Скажите «да, переносим» — и шаги 3–6 агент сделает сам и проверит.

## Вариант B — оставить папку на месте, но исключить её из синхронизации Drive

Названия пунктов меняются от версии к версии, поэтому если ваш экран не совпадает с описанием — пришлите скриншот окна, подстрою шаги.

1. В трее (правый нижний угол, рядом с часами) найдите значок Google Drive — сине-зелёный треугольник. Нажмите по нему правой кнопкой или откройте меню из трёх точек.
   Ожидаемый результат: меню с пунктами настроек («Preferences» / «Настройки»).
2. Зайдите в настройки и найдите раздел «Backup and sync» («Резервное копирование и синхронизация»).
   Ожидаемый результат: список папок компьютера, которые Drive бэкапит (обычно Desktop, Documents, Downloads, Pictures) с кнопкой «Manage backups» / «Choose folders».
3. Уберите галочку с той папки, внутри которой лежит проект, или удалите её из списка бэкапа. Если папка проекта задана отдельным «Sync these folders» — снимите её оттуда.
   Ожидаемый результат: Drive перестаёт показывать прогресс по файлам проекта.
4. Проверьте через минуту: в трее значок Drive не активен по нашему пути, а в `C:\Users\Administrator\lox-voice` новые `desktop.ini` больше не появляются.
   Быстрая проверка одной командой: `node scripts/sweep-windows-junk.mjs` (должно быть `no Windows junk`), затем `dir /s /b desktop.ini` в командной строке — новых файлов нет.
5. Если нужно просто выдохнуть прямо сейчас, в том же меню есть «Pause sync» («Приостановить синхронизацию») — до 24 часов. Это временная мера, она не отменяет пункт про `.env` в облаке.

## Что делать с токенами, которые уже уехали в облако

1. Зайдите на drive.google.com и проверьте, есть ли там `lox-voice` со `.env.local` / `.env.test` внутри.
2. Если есть — удалите папку проекта из Drive (не с диска: сначала убедитесь, что синхронизация этого пути выключена, иначе удаление уйдёт и на диске).
3. После этого считается, что токены могли быть прочитаны, и их нужно выпустить заново: Vercel API token, Blob storage token, токен GitHub. Это отдельная задача — скажите, и агент распишет каждый выпуск по шагам.
